# 使用与实现参考

安装、配置和界面预览见 [项目 README](../README.md)。本页保留完整操作说明、接口约定和验证记录。

## 实现与验证

启动面板选择工作区、模型和智能体预设，编辑一次性首条消息；成功后绑定会话并留在看板。卡片显示执行中、待审批、待回答、出错、空闲，以及会话丢失、归档或状态不可用。「需要我处理」按工作区汇集未完成任务的待审批、待回答、待验收、失败和待发送返工意见；没有需要处理的任务就不显示。多个页面共用各自的一条 SSE 连接，自动同步任务和状态，断线后恢复完整快照。

Host 使用 `connection.fetch.register()` 提供 RPC、SSE 和 MCP 精确路由，Client 操作使用 `connection.rpc.call()`，实时通知使用同源 Fetch 流。外部插件通过 `taskService` 调用同一业务逻辑。当前通用服务、SQLite 和 MCP 契约见 [接入文档](task-service.md)。此前实现与验证历史保留在 [步骤 1](step-1-verification.md)、[步骤 2](step-2-verification.md)、[步骤 3](step-3-verification.md)、[步骤 4](step-4-verification.md)、[步骤 5](step-5-verification.md) 和 [M3](m3-verification.md)，其中 JSON 存储描述属于旧版本。

当前新建与详情抽屉见 [README 的界面预览](../README.md#界面预览)；此前的弹框、工作区与模型偏好验证留存于[看板与弹框验证](ui-verification.md)。

打开已有任务的「详情」，可重新选择工作区和模型，或选回「未分组」和「使用默认模型」，然后保存。工作区筛选随保存结果更新；已打开的对话不受影响。

任务看板默认跟随 DSH 外观，不依赖主题插件即可运行。安装 `@tavlo-dsh/dsh-plugin-paper-theme` 后，顶部「看板设置」中出现「任务卡片外观」，可选「跟随全局」「iOS 圆角」或「纸面主题」。独立选择只改变看板，仍跟随 DSH 的亮暗模式；切换会保留任务数据、草稿和搜索。纸面样式原始接入见 [全局主题适配](global-theme-adaptation.md)，删除与交互基线见 [任务删除与交互调整](task-controls-verification.md)。

## 使用看板

**手记概览。** 默认收起，可通过工具栏的图表图标展开。关闭时，展开的任务列均分可用空间；列不足以容纳最小宽度时可横向滚动。打开时，空间充足则停靠在左侧，较窄则浮在看板上，不挤窄任务列。设置记在当前浏览器。完成率、优先级、工作区与模型分布随搜索、工作区、标签和优先级筛选；今日及近七天完成数按本地日期和当前已完成任务计算，平均周转仅计算有完成时间的任务，不以会话耗时替代。

到期分布仅统计未完成任务，按已逾期、今天、明天和后 2–7 天分组。点击一行筛选，再点一次或点击日期筛选标签即可取消。日期筛选不改变概览的统计范围；小窗口仍可在筛选菜单中选择日期。

概览下方的「待处理清单」按待审批、待回答、出错、逾期、未来 7 天到期、高优先级（P0/P1）的顺序挑选最多 5 项未完成任务，并显示原因。「最近完成」按实际完成时间倒序显示最多 5 项，不限于最近 7 天，忽略没有完成时间的旧记录。两份清单都跟随工作区、搜索、标签和优先级筛选；到期筛选只影响待处理清单。点任一行打开任务详情。

**任务文件。** 在新建或详情抽屉点「添加文件」，也可拖入文件或粘贴剪贴板中的文件。每张卡最多 10 个文件，每个不超过 10 MiB（宿主可能限制图片大小）。文件行显示名称、大小与上传状态；PNG、JPEG、WebP 可点缩略图预览，其他格式直接下载。下载和移除使用每行右侧的图标。建卡先保存文字，再上传文件；失败项可在详情中重试，刷新后未上传文件需重新选择。上传或移除附件不会要求放弃正在编辑的文字。启动面板默认勾选「随首条消息发送任务附件」：图片随首条消息发送，PDF、Word、Excel、文本等普通文件以会话附件发送，供 Agent 使用工具读取。取消勾选只发文字；发送图片仍需要支持图片输入的模型。若所选附件还未上传成功，请在详情中重试，或取消勾选以仅发送文字。恢复启动沿用该次保存的附件，启动后增删文件不会改变已发送的内容。

**列与拖拽。** 点顶部「看板设置 → 管理列」，在居中弹框输入列名、选择所属阶段（默认「进行中」），再点「添加列」。看板末尾不单放按钮。例如「待验收」可以是一列，但对旧工具仍属于「进行中」。列头铅笔可改名。拖动列头左侧的把手，把列拖到想放的位置。列间插入线和浮动标签会提示松手后的位置；在看板外松手或按 Esc 可取消。单击把手打开「管理列」，聚焦把手也可用左右方向键移动。列排序对整个看板生效（包括当前处于筛选视图时）。管理面板也可拖动列，或用上下箭头调整。只有空自定义列可删；被其他工作区的卡片引用也不能删。

在完整视图拖动任务标题、描述或卡片空白处都能移卡。鼠标单击仍打开详情，触屏轻扫保持滚动，长按后再拖动。菜单、启动和打开对话按钮不触发拖动。放到另一张卡的上半部／下半部可插到它之前／之后，放到列的空白处则追加。Esc 取消，不写入也不打开详情。搜索、筛选和最近完成视图不提供拖拽，可用卡片菜单明确选择目标列；点「查看全部」后可排列完成列。键盘可以使用把手，或在菜单选择前移／后移。

侧栏打开「任务」即看到所有工作区和未分组任务。点击「新建任务」，在右侧抽屉填写标题和可选描述、工作区与模型偏好。默认未分组、使用默认模型，只有标题必填。列底「新建」预选该列分类。保存成功后任务出现在所选分类；工作区/模型仅作为后续启动任务的偏好保存，本步不创建会话。桌面拖动抽屉左边缘调整宽度，松手后记住；键盘聚焦分隔条用左右键微调，Home/End 到最窄／最宽。窄屏全宽，不显示分隔条。

每卡可选一个全局彩色标签、优先级和截止日；在「管理标签」弹框中改名或改色不改任务历史。有引用的标签不能删除。详情支持 Markdown 描述预览。切换到「动态」可独立发布纯文本评论，或查看按本地日期分组、最新在上的时间轴。时间线用不同图标区分创建、字段修改、移列、完成、重开、文件、评论和会话绑定，并显示来源与时间；修改的字段各有独立标签。可切换到「仅评论」。点「更早的动态」继续回看；实时更新时已加载的旧记录和阅读位置会保留。切回「详情」不会丢掉编辑或评论草稿。搜索支持任务 ID、标题、完整描述和评论，可叠加工作区、标签、优先级和日期；只命中评论时卡片显示摘要。今天到期不算逾期，已完成卡不参与到期筛选。

点击卡片标题或正文，在右侧抽屉查看任务标题、所在列和会话状态；点击标题下的复制图标复制完整任务 ID。修改标题、描述或属性后点「保存修改」。图片、评论等变化不会制造文字编辑冲突；另一页真正修改了标题、描述或属性时，保留本地输入，不允许覆盖新版本。「放弃本地修改并载入」会先确认，取消后继续编辑。详情文字与属性草稿保存在当前标签页，刷新后重新打开同一任务可恢复；恢复时仍检查原始编辑基线。保存结果未知时只重试原请求，不自动发送；任务数据源变化时保留草稿并暂停重试，需返回原数据源处理。按 Esc、点关闭或遮罩退出，未保存的详情修改会先询问是否放弃；关闭抽屉不会清空看板筛选。

卡片右上「任务操作」菜单可改列或删除，详情抽屉右上也有删除入口。没有待保存修改时，详情底部优先提供打开对话、启动或恢复启动的单个入口；已有对话时仍可从「任务操作」打开启动面板。启动与删除仍需单独确认。删除后移除任务卡片，关联对话保留并继续运行。尚未结束的启动请求需先恢复或结束。删除与其他更新发生版本冲突时，需要刷新并重新确认；结果未知时重试同一次删除。

顶部工作区选择器默认「全部工作区」，可搜索并切换到 DSH 配置的任一工作区（包括暂无任务的工作区），也可单独查看「未分组」。搜索可叠加工作区及其他筛选；列计数显示「匹配数 / 总数」。「清除筛选」只清除筛选菜单内的条件，不切换工作区。点击列标题可收成窄栏，再点展开；空的非完成自定义列默认收窄。展开、折叠和完成列范围记在当前浏览器。每个已完成列超过 4 项时，默认只显示最近完成的 4 项；没有完成时间的旧卡按更新时间排序。点列头「查看全部」展开这一列。搜索或筛选不受最近 4 项限制；可用「可开始」找出没有前置阻塞、尚未绑定或启动的任务。每个展开的列底部都只有「新建」。

看板使用固定的卡片布局，不提供密度切换。选项可输入关键词按名称、编码或模型分组检索，用上下键选择、Enter 确认、Esc 取消。在新建抽屉的标签和优先级中输入新名称，可直接选「新建」。

其他页面新建或改列后，卡片和计数自动更新，当前草稿、搜索和筛选条件保留。底部显示实时连接状态；断线时提示任务可能过期并自动重连，顶部「刷新」也可重新读取 Host。实时通知与当前操作交错产生版本冲突时，会显示原先想要移入的分类；刷新后可按新数据重新选择。

创建期间禁止重复提交。普通业务失败保留可编辑的输入；创建结果未知时锁定原输入，点击「重试」复用同一创建请求，避免重复任务。草稿和待确认请求保存在当前标签页的 `sessionStorage`，页面刷新后可继续；成功后清除。浏览器禁用该存储时只在当前 Client 生命周期内保留，关闭标签页或清除浏览器存储也会丢失草稿。

改列结果未知时先刷新确认已保存的分类，避免盲目重复写入。列表加载失败时保留上次已加载的卡片、提示数据可能过期，并暂停写操作；重试成功后恢复。存储状态不确定时隐藏旧卡片并提示重新启用插件或重启 DSH。

## 启动与恢复

如果大模型已经在当前 DSH 对话里做这项工作，让它用**原生** `tasks_create` 创建「进行中」任务。卡片会显示「查看进度」，直接回到这个对话，不会重复启动。只请它记一条待办时，保留默认的「待办」即可。手动移入「进行中」不会关联对话，也不会启动 Agent。这类卡片显示「未关联对话」；如果需要 Agent 执行，可点「新建对话」，检查首条消息后再点「新建并启动」。有未完成的前置任务时，仍须先完成前置任务。

待办卡片用「开始任务」打开启动配置。工作区和模型预填任务偏好，预设可选择宿主目录中的可用项；首条消息预填标题和描述，对消息正文的临时修改不回写任务。若填写验收标准，Host 固定该版本随首条消息发送。启动成功时，所选工作区与会话绑定一起回填任务；选择「未分组」会清除任务原有工作区归属，并使用宿主默认目录。取消或尚未完成启动时不提前改变任务归属。

「思考强度」是下拉框，只列出当前模型支持的档位，也可选择「使用模型默认强度」。跟随默认模型时，会显示当前强度；修改档位会选定当前的默认模型。选择具体模型启动任务会同时更新 DSH 全局默认模型，面板有明确提示。模型正常执行需要可用的模型配置和凭据。

启动成功后留在看板，只把 `todo` 自动改为 `doing`。需要继续对话时点击「查看进度」或「打开对话」。执行中、待审批、空闲等只表示对话状态，不会自动完成任务。手工任务仍可用卡片菜单「标记完成」或移入已完成阶段；已有待验收或退回的交付时不能用改列跳过验收。改列不会停止正在运行的会话。已有空闲对话时，可在卡片或任务详情的「…」菜单点「新开一个对话」，然后编辑首条消息。点「新建并启动」才会创建新对话，旧对话仍可从历史中打开；取消不会改变当前绑定。对话正在执行、等待审批或回答时，不能另建。看板暂时无法获取原对话状态时，仍可编辑并提交空白新对话；创建前服务端会重新检查，确实忙碌或无法读取真实状态时不会创建。原对话状态未知时不能选择 Fork。

**空白、Fork 和打开原件的区别：**

- 空白新对话不继承聊天记录，可以重新选择工作区和智能体预设。
- Fork 从任务当前绑定的上一对话分出新对话，继承到宿主最近已完成轮次的历史边界，沿用原对话的目录和预设。输入框里的文字和勾选的任务附件只发给子对话。没有已完成轮次时不能按此方式 Fork；从已归档的原件 Fork 不会将原件移出归档。
- 要在原对话里继续，请点「打开对话」，不要选 Fork。若原件已归档，确认恢复后才会打开它；取消不改变归档状态。

**中断后怎么办？** 浏览器未收到结果时保留原请求，重新打开面板可核对进度。目标会话 ID 已记录时，「恢复启动」沿用同一会话和首条消息请求；进入投递阶段后不允许放弃。若宿主可能已创建分支，但面板未能取得子会话 ID，面板不会再 Fork，也不会发送首条消息。此时可以明确结束本次操作，任务仍绑定原对话；宿主中可能留有一个未绑定的分支。

状态不落库。Host 对活跃会话 ID 去重，响应宿主事件并每 `statusRefreshMs`（默认 2000 ms，范围 500–60000）被动采样；该采样补足 DSH `observeState` 不通知独立 pending-input 变化的限制。只在空闲且日志游标改变时读取最近 turn 结果。每个浏览器仍只有一条任务 SSE，增加卡片不会增加浏览器会话连接。待审批和待回答在现有对话中处理。

## 单卡交付与验收

1. 在新建或详情填写「验收标准」。可用「前置任务」关联其他卡。前置未完成时卡片列出阻塞项；点击可跳到对应卡片，前置完成后只解锁，不代为启动。
2. 选择「开始任务」。任务绑定当前会话；该会话可用 `tasks_submit_delivery` 提交摘要、可选的验证结果、未验证事项和链接。提交后「需要我处理」显示待验收；会话空闲但未提交时不算待验收。
3. 在任务抽屉的「Agent 交付」页签查看证据。页签位于「动态」之后，点卡片的「验收成果」或「需要我处理」中的交付提醒可直接打开。证据由 Agent 提供，不代表独立验证。点击「接受并完成」记录验收并移动卡片；也可写明原因后「退回修改」。
4. 退回不会立即运行模型。点击「把意见发给 Agent」才把反馈投递到原会话。Agent 修改后可再次提交；不另建会话。关单或验收不会合并代码、回写 TAPD 或启动后续卡。

对已有对话或预设没有提供提交工具的任务，可打开原会话核对结果；不会把聊天结束推断成交付完成。保留手动完成路径仅用于没有待验收或被退回交付的任务。

## 存储与操作

任务复用宿主发布的 `DomainFacility` 和 SQLite 后端，默认文件为 `$DSH_HOME/storages/tasks.sqlite`，不修改其他插件的存储路由。SQLite domain `tasks` 已升到 v8；v5 任务按原阶段回填默认列，v6/v7 升级不伪造动态、完成时间或附件。首次安装仍支持只读导入 v1–v4 JSON，原文件保留不变。中断恢复、路径配置和降级限制见 [接入文档](task-service.md#sqlite-迁移与运维)。

删除仍用同一条记录写入移除正文、绑定、更新和启动历史，仅保留任务 ID、创建请求 ID、删除版本与时间的最小回执；回执不计入 `maxTasks`。客户端不能指定存储文件路径。

各操作均通过 `{ operation, input }` 调用现有 RPC endpoint：

| operation | input | 成功 value |
| --- | --- | --- |
| `capabilities` | `{}` | 契约版本、操作列表、能力与限制 |
| `list` | `{ stage?, workspaceId?, provider?, externalRef?, limit?, offset? }`；旧 `{}` 保持兼容 | `{ tasks, total? }`；分页时有 `total` |
| `get` | `{ taskId }` | `{ task }` |
| `create` | `{ requestId, title, brief?, stage?, workspaceId?, model?, externalRef? }` | `{ task }` |
| `update` | `{ requestId, taskId, expectedRevision, patch }` | `{ task, mutation: { requestId, appliedRevision, replayed } }` |
| `set-stage` | `{ taskId, expectedRevision, stage }` | `{ task }` |
| `delete` | `{ taskId, expectedRevision }` | `{ taskId, revision }`，重复删除返回同一回执 |
| `options` | `{}` | `{ workspaces, groups, presets, workspaceStatus, modelStatus, modelFailures, defaultModel? }` |
| `images` | `{ taskId?, launchRequestId? }`；提供启动请求 ID 时必须提供任务 ID | `{ limits, images, revision?, launchRequestId? }`；仅允许读取当前未结束启动的冻结图片 |
| `files` | `{ taskId?, launchRequestId? }`；提供启动请求 ID 时必须提供任务 ID | `{ limits, files, revision?, launchRequestId? }`；启动预览包含固定的图片和普通文件 |
| `launch` | `{ taskId, expectedRevision, requestId, content, workspaceId?, model?, agentPreset?, replaceActive?, includeFiles?, includeImages?, forkFromSessionId? }`；Fork 的限制见[服务契约](task-service.md#从当前任务会话-fork)。 | `{ task, sessionId }` |
| `resume-launch` | `{ taskId, requestId }` | `{ task, sessionId }` |
| `abandon-launch` | `{ taskId, requestId, expectedRevision }` | `{ task }` |

创建默认进入 `todo`，`revision` 为 1；`set-stage` 接受 `todo / doing / done`，成功后递增版本。`model` 为 `{ provider, model, reasoningEffort? }`，空偏好不写入记录。工作区与模型是弱引用，新创建时校验当前目录是否存在；已有记录的引用失效不影响列表和原请求重试。

工作区通过 `ctx.get('workspaceRegistry').list()`、模型通过 `ctx.get('sessionController').modelCatalog()` 读取。目录服务可选，没有服务时仍允许不绑定创建。`requestId` 是 1–128 字符的标识，接受字母、数字及 `._~-`；创建结果未知时必须复用同一标识和全部相同参数重试，包含初始分类、工作区和模型。相同请求返回当前已有任务，参数不同返回 `tasks/request-conflict`。创建请求元数据与任务一同持久化，不出现在 RPC 的 TaskRecord 中。

`cordis.patch.yml` 可配置 `maxTitleLength`（默认 200）、`maxBriefLength`（默认 20000）和 `maxTasks`（默认 10000）。降低限额不会使已有记录失效，也不阻止重放已完成的创建请求。

`maxLaunchesPerTask` 默认 1000，限制新启动的历史条数；已有请求仍可恢复或重放。任务公开当前 `launch` 的请求与进度，完整 `_launches` 去重历史只保存在 Host。启动响应只表示消息已被 DSH 接收，执行成功与否由会话状态显示。请求取消不意味着已执行操作回滚；插件重新加载后不会自动发送未完成请求，需用户点「恢复启动」。

实时通道为 GET `/api/dsh-plugin-tasks/events`，复用 Connection 的鉴权与 owner 检查。每次连接从完整快照开始，再发送已持久化的任务变更。`eventBufferBytes` 限制每个连接的待发队列（默认 32 MiB，范围 64 KiB–256 MiB）；慢客户端超限后断开并通过快照恢复。完整快照超过该上限时返回 HTTP 503、`tasks/events-too-large`，需要提高限额才能恢复实时流；RPC 读取仍可用。`eventHeartbeatMs` 默认 15000，范围 1000–60000，代理需要允许流式响应并保持连接超过心跳间隔。

Client 以 1、2、4、8、15 秒退避重连，上限 15 秒；稳定连接 30 秒后恢复初始退避。首次快照等待上限 30 秒，已建立连接连续 90 秒没有收到数据时重新连接。完整页面离开时暂停，返回时恢复；看板内的卡片和视图切换不增加连接。插件卸载关闭流并停止重连。

普通写入失败返回 `tasks/persistence-failed`；后端报告结果不确定时返回 `tasks/persistence-unknown`，停止返回可能过期的数据，需重新启用插件或重启 Host 后恢复。损坏记录会使插件初始化失败，不能用空列表掩盖。插件卸载会等待已经接纳的操作完成，再关闭 domain。

SQLite 按行更新任务，任务与更新回执在同一行提交。Domain 和任务队列保护同一 Host 内的并发；由于读取仍来自内存快照，同一数据库需要由一个 Host 进程管理。当前没有历史统计接口或多记录事务接口。

## 结构

| 文件 | 作用 |
| --- | --- |
| `package.json` | 包清单；`dsh.bundle.patch` 声明 Loader 补丁，`dsh.client` 声明浏览器半边 |
| `cordis.patch.yml` | 插入 `tavlo-tasks` 这一行 |
| `index.js` | Host 半边，公开 TaskService 并注册鉴权 RPC、SSE 和 MCP 路由 |
| `task-storage.js` | SQLite 生命周期、旧 domain 校验导入及中断恢复 |
| `task-service.js` / `.d.ts` | 通用服务外观与第三方插件类型契约 |
| `task-mcp.js` | 复用 TaskService 的 MCP 工具与 Streamable HTTP 适配 |
| `task-mcp-client.js` / `bin/tasks-mcp.js` | 独立 API 身份与 stdio 桥接 |
| `task-schema.js` | 持久化字段、创建元数据和输入校验 |
| `task-store.js` | 列表、创建去重、版本更新与操作清理 |
| `task-options.js` | Host 工作区/模型目录读取、显式偏好存在性检查 |
| `task-events.js` | 有队列上限的实时事件流、心跳、取消和卸载清理 |
| `task-sessions.js` | Session 创建、模型选择、消息去重重放和状态聚合 |
| `client.js` | 浏览器半边，看板与操作、共享实时流和断线恢复 |
| `locale/*.json` | 插件管理里显示的标题与描述 |
