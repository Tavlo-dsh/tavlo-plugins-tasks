# 步骤 4：任务实时同步验证

2026-11-17，DSH 0.2.2-rc.1，现有 `web` profile 的本地 link 安装。任务实时同步已完成；任务会话关联、执行状态与告警条保留到单任务启动阶段。

## 实现

Host 通过 Connection 的精确 GET `/api/dsh-plugin-tasks/events` 提供 SSE，复用共享 API 的鉴权、Origin 检查和 owner 限制。存储队列中的 `watch()` 负责读取完整快照并登记订阅，持久化写入成功后发送带 `streamId / sequence` 的 `upsert`；创建请求重放和普通写入失败不发布变更。存储结果不确定时发送 `unavailable`，所有页面隐藏旧记录，新的订阅返回 503，直到存储重新打开。

每个连接具有待发字节上限，默认 32 MiB，可通过 `eventBufferBytes` 配置。慢客户端超限时解除订阅并关闭流；初始快照过大返回 503、`tasks/events-too-large`，提高限额后恢复，RPC 仍可读取。`eventHeartbeatMs` 默认 15 秒。请求 AbortSignal、ReadableStream 取消与插件卸载均释放流、订阅及心跳。

Client 在插件生命周期内共享一条同源 Fetch 流，识别完整快照、任务变更和存储不可用事件。RPC 列表响应不能覆盖新事件，写响应按版本合并；新的 Host 身份使完整快照成为恢复依据，旧 Host 的迟到写响应不能覆盖它。连接结束、序号缺口、错误帧或超时会自动重连，退避上限 15 秒。页面离开暂停、返回恢复，卸载停止重连；草稿、搜索、筛选和待确认的请求保留。

## 自动验证

`npm test`：55 项通过，其中新增 15 项实时流测试。测试直接运行发布版 Connection、WebServer、Storage Domain 与 JSON 后端，并执行实际 `client.js` factory。

- 真实 HTTP 的首次快照、任务变更、重启后新身份与完整记录恢复，以及无凭据、非法 Origin、非 owner 和错误 method 拒绝。
- 写入与首次快照交错时不漏任务；创建重放及写入失败不发布变更。
- 慢消费者队列上限、超大首次快照、取消期间订阅尚未就绪、读流取消和卸载释放。
- 两个 Client 自动同步、任务数量与组件重渲染不增加连接，草稿和搜索保留。
- 迟到列表、旧快照和旧 Host 写响应不能覆盖新记录；存储不确定时所有页面隐藏旧数据。
- UTF-8 分片与 CRLF 解析、序号缺口重连、退避上限、首次快照超时、无数据超时及页面生命周期清理。

## 真实页面

使用 `dsh --profile web --patch <临时 storage.overlay.yml> --no-open --port 0` 启动测试 Host；JSON root 指向独立临时目录。Playwright 控制无窗口 Edge，同一浏览器上下文打开两个真实 DSH 页面。

页面验收通过：一页用新建弹框创建任务，另一页无需刷新即出现卡片；卡片菜单改到进行中、已完成时另一页自动更新；另一页的新建草稿和搜索条件保留。开始时每页仅打开一条任务流。主动取消一页的实际 Fetch 请求后，界面显示断开并自动重连，完整快照恢复当前分类。

保存完整存储记录后，停止测试 Host 进程并在相同端口、相同临时存储启动新进程。两个既有页面自动重连，重启前后的完整 JSON 记录一致；重启后新建的任务继续自动同步，两页卡片的 ID、分类和标题一致。浏览器没有 `pageerror`。

测试结束后关闭浏览器和本次启动的 Host 进程树。正式任务文件的 SHA-256 在验证前后相同，本次未写入正式任务库。
