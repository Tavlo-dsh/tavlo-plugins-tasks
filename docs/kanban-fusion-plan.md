# Tavlo 任务看板融合计划

状态：评审稿，D1「总看板范围」已确认。当前进度及仍待确认的 D2（截图是否随首条消息发送）、D3（是否导入上游存量）见[融合进度](kanban-fusion-progress.md)。可重跑的基线、迁移及事件兼容规则见 [F0 契约](kanban-fusion-f0.md)。

以 `tavlo-plugins-tasks` 为产品和数据底座，以 `dsh-kanban` 为任务卡与看板交互蓝本。融合后，卡片本身能承载需求、截图和交接记录；需要执行时，再从同一张卡启动和跟踪会话。不安装两套看板来模拟融合，也不让两份任务数据双向同步。

## 1. 首版用户旅程

添加「待验收」列 → 从右侧抽屉建卡，填写 Markdown 描述、标签、优先级、截止日期并粘贴截图 → 拖动卡片改变排序或阶段 → 从卡片启动会话 → 在看板进入待审批或待回答的会话处理 → 回到详情留评论、移到待验收 → 验收后移到已完成，回看时间轴。刷新或打开另一标签页，任务、列和排序保持一致。

首版包含这条流程，不要求默认新增第四列。不默认做按工作区独立流程、非空列批量迁移、远端状态回写、批量启动或旧看板双向同步。附件随执行消息发送、一次性导入分别由 D2、D3 决定。发布基线先按 DSH `0.2.2-rc.1` Web 验证；桌面端需独立验收，不能沿用上游的兼容声明。

## 2. 看板从左到右

| 区域 | 首版行为 |
| --- | --- |
| 侧栏与顶栏左侧 | 保留 DSH 侧栏「任务」和一个 Tavlo 总看板。默认选中「全部工作区」，包含未分组任务；也可只查看「未分组」或指定工作区。切换范围只筛任务，不导航会话，也不切换列或标签定义。 |
| 顶栏中间 | 搜索任务 ID、标题、完整描述和评论；只命中评论时显示摘要。工作区、标签、优先级和截止日期可与搜索叠加，条件可分开清除。日期至少提供「今天到期」「已逾期」。 |
| 顶栏右侧与提醒 | 保留全局「新建任务」；「看板设置」集中提供刷新、管理列和管理标签。沿用未完成任务的全局待审批、待回答和出错提示，可打开原会话；不把逾期混入会话提醒。 |
| 列头、列底和列管理 | 列头显示名称、折叠入口和匹配数／总数；列底「＋ 新建任务」预选此列。按界面反馈，「添加列」集中在管理列抽屉，不在看板末尾占位。改名可从列头进入，拖动列的排序放在管理列面板。多列和窄屏允许横向滚动，不压缩卡片到不可读。 |
| 卡片 | 优先显示标题、简短描述、标签、优先级和到期信息；图片、评论用计数。保留会话状态和打开／启动／恢复入口。点击标题或卡片非控件区域开详情，内嵌按钮和拖拽不误开。 |
| 完成列与底部 | 保留最近更新 10 条和「查看全部」；最近视图不当作手工排序视图。保留数量、实时连接、断线和加载失败提示。空看板、筛选无结果和读取失败要能区分。 |

## 3. 右侧抽屉与任务详情

- **入口与布局：**全局、列内新建及卡片详情共用抽屉。桌面从右侧打开，可调宽并记住宽度；窄屏全宽。顶部是标题和可复制的任务 ID（已有卡），中部是列、标签、优先级、截止日期、Markdown 描述和图片，下部是评论、活动以及会话关联。底部操作固定可达，关闭不重置筛选、滚动或触发控件焦点。
- **新建与编辑：**仍然只有标题必填。新建保留工作区和模型偏好，详情展示这些偏好，启动时仍可临时覆盖。详情可编辑标题、描述及看板属性；保留 `brief` 字段与 Tavlo 长度约束，用宿主 Markdown 渲染预览，不执行 HTML。正文保存、评论发布、附件操作各自有明确反馈。移列和正文保存都不自动启动会话。
- **草稿与冲突：**保留新建文本草稿和未知结果重试，同一提交复用原请求 ID。详情有未保存修改时关闭需提示；有其他页面或连接器更新时，不自动覆盖本地草稿，也不把过时草稿强行写回。删除任务仍须确认，不删除或停止关联会话；未完成的启动先按现有流程恢复或结束。
- **标签与时间：**建议首版每卡一个可选彩色标签，支持新增、改名、改色；用稳定 ID，改名不批量改卡，有引用的标签先解除引用再删除。优先级可选 P0/P1/P2。截止日期存 `YYYY-MM-DD`；今天到期不算逾期，已完成任务不参与到期或逾期筛选。任务进入 `done`（含直接在完成列新建）时记录完成时间，在两个 `done` 列之间移动不重记。重开后当前完成时间清空，历史完成事件保留；存量完成时间未知时不由 `updatedAt` 推测。
- **图片与评论：**支持选择、粘贴、拖入 PNG/JPEG/WebP，按宿主能力校验和预览。建卡先提交文字，再以已保存卡片 ID 上传；部分失败保留成功项和待重试项，不重建卡片。未上传的文件只在当前页面保留，提示刷新后需重新选择。评论先用纯文本，失败保留输入；活动记录展示操作、时间和 Host 能识别的来源（用户、Agent、连接器或系统）。

详情底部保留保存和打开／启动／恢复任务；启动仍有独立确认步骤。删除放在次要操作中，不与「保存」并排竞争。保留 Tavlo 已有的「跟随全局／iOS 圆角／纸面主题」和 `tavlo-tasks.appearance` 插槽；抽屉复用同一套外观，不整体搬上游皮肤。抽屉采用宿主模态层协调 Esc 和焦点，不在原生 `showModal()` 上直接叠加宿主的图片预览。

## 4. 列、任务状态与会话状态

列回答「卡片在哪一步」，`stage` 回答「对外属于哪个阶段」，会话状态回答「Agent 正在做什么」。例如「开发中 → 待验收」是一次跨列移动，但两个列都属于 `doing`；「已交付」可以属于 `done`，与会话此刻是否空闲无关。

- **列归属：**总看板共享一套列和标签定义，不按工作区独立配置。默认保留「待开始／进行中／已完成」，各有一个不能删除的默认列，可改名和排序。自定义列拥有稳定 `columnId`，创建时默认属于 `doing`，可显式选择其它阶段；首版不开放更改已建列的阶段归属。任务按列 ID 归属，不用标题或位置推断阶段；Host 必须保证列和 `stage` 一致。
- **兼容旧入口：**只传 `stage` 创建任务时进入对应默认列；对已处于该阶段的任务调用 `set-stage` 不应挪掉所在自定义列，保留原有版本递增语义。跨阶段更新进入目标阶段的默认列，兼容入口不改 `position`。旧数据库现有任务按原 `stage` 进入默认列，保持原排序和标识。
- **卡片拖拽：**支持跨列、空列及完整视图内同列排序，保留键盘和「移动到」菜单。用实际卡片 ID 作为顺序锚点，不把筛选结果的下标当全列位置；筛选或「最近完成」视图不提供同列调序，跨列可通过明确目标的菜单完成。触屏拖动不得抢占正常滚动。
- **拖拽并发：**取消无写入。Host 校验当前任务版本、目标列与顺序锚点；写入失败或版本冲突时撤销该次乐观移动，与最新快照合并，不回滚其他标签页的操作。成功后发布更新，刷新、重启或打开第二标签页后，任务顺序一致。
- **删列规则：**首版允许删空的自定义列，Host 按实际卡片数判断，不能用当前筛选的可见数量。非空列显示任务数和移卡指引，不静默迁移或删卡。待有可靠多记录提交或可恢复迁移方案，再开放「选择目标列并批量迁移」。

## 5. 会话、接口与存储

- **会话执行：**保留工作区、模型、Agent 预设和可编辑首条消息；已有活跃会话优先打开，保留替换限制。成功提交首条消息后，只有当时仍为 `todo` 的任务自动进入默认 `doing` 列。拖卡不启动或停止会话，会话空闲不完结任务；启动失败复用原请求、会话和消息标识。首条消息预填任务标识和描述，保留描述中的验收要求。D2 若要求带图，须验证附件与消息一起成功投递，且恢复仍使用原附件引用；不能静默省去截图。
- **单一服务：**浏览器、MCP 和连接器继续调用 `taskService`。保留现有 `list({})`、`stage`、来源去重、版本与重放语义；新操作或字段按能力声明扩展。确保已配置 Tavlo MCP 的 Agent 至少可查完整任务、按列移动并评论。新增能力不默认开放 MCP 启动、删除或远端写回，连接器继续负责 TAPD/GitHub 等远端同步。
- **SQLite 与动态：**列、标签、卡片、排序和动态都由 Tavlo 管理；附件存原生引用，不存于卡片正文或 SSE。活动记录与已提交业务变更一致：创建、字段修改、跨列、完成／重开、评论、图片和会话启动／绑定可追溯；同列调序、瞬时运行状态、重复请求不刷动态。看板同步当前状态，保留每页面一条 SSE；详情按需加载正文之外的历史和附件，不能把全部动态塞入完整快照。
- **存量升级：**以当前 SQLite/domain v5 为升级起点，同时回归旧 v1–v4 JSON 导入链路。保留任务 ID、外部来源、排序、会话关联、待恢复启动及创建／更新／删除回执。迁移支持重复执行与异常中断恢复，失败时不得清库重建；旧 JSON 和升级前备份保持不变。若 D3 有真实需求，单独做可预览、可去重的一次性导入，验证工作区及图片引用，不做并行同步。

## 6. 实施顺序

| 里程碑 | 交付切片 | 完成条件 |
| --- | --- | --- |
| F0 基线与契约 | 对齐当前工作区的 TaskService、SQLite 和 MCP 基线；定列归属、迁移版本、动态写入和事件兼容方案；验证拖拽依赖和原生预览能否与现有 DSH 插件加载方式配合。 | 记录确切基线；冻结需兼容的旧操作与数据样本；确认 D1。 |
| F1 新建与详情抽屉 | 在现有三列上交付共享的宿主模态层抽屉、标题/描述编辑和原有执行入口，不改 SQLite schema。 | 新建、重新打开编辑、Esc、窄屏、焦点恢复和旧请求重试均可用；原有启动入口和外观无回归。 |
| F2 列和拖拽 | 新增/改名/排序/删空列，卡片排序与跨列移动；扩展同步和存量迁移。 | 老卡顺序保留；手动加「待验收」可用；刷新、重启、双标签页、冲突及旧接口验证通过。 |
| F3 卡片属性与动态 | 标签管理、优先级、日期、Markdown、评论、活动和组合查找。 | 查询能命中评论；完成、重开、同阶段异列移动有记录，列名修改不制造卡片移列记录。 |
| F4 任务图片 | 原生附件上传、预览、移除；若 D2 要求，同时交付带图启动与恢复。 | 单图失败可单独重试且不重复建卡；Host 不支持图片时文本流程照常。带图启动纳入时，另验证真实会话收图和重复启动保护。 |
| F5 联动与发布验收 | 验证 Agent/MCP、连接器和现有执行链路；打包安装、隔离升级、恢复演练。 | 首版用户旅程、基线回归及新增用例通过；保留上游直接复用代码的 MIT 许可和版权声明。 |

F2–F4 在 Tavlo 同一看板、右抽屉和服务内交付。F5 的 Web 候选已经过隔离安装、升级及恢复，证据见[融合进度](kanban-fusion-progress.md)和[F5 演练](kanban-fusion-f5.md)。D2 默认启动不送图；变更需独立验收。尚未发布，不用 Web 结果代替桌面与实体触屏验收。
