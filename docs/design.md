# 任务面板（Task Board）设计

DSH 插件，包名 `dsh-plugin-tasks`，Loader entry `tavlo-tasks`。

## 1. 定位

一句话：

> **把一件「要做的事」变成一张能一键发射、并且能实时看到状态的卡片。**

两个核心价值，其余都是副产品：

- **发射**：一键带上工作区、模型、预设和执行说明，起一个对话。
- **状态**：每张卡实时反映它那个活跃对话的状态——执行中、待审批、空闲。看板回答的是「**现在有什么在等我**」，这比「我要做什么」更值钱。

看板只是「状态」这一维的呈现形式，产品本体是上面两件事。

## 2. 已定的约束

1. 一个任务同一时刻**只绑定一个活跃对话**，卡片状态以活跃对话为准。
2. 看板列 = **手工状态**（待开始 / 进行中 / 已完成）；「要你动」提成独立告警层。
3. 拖拽**只做分类**，永不启动对话。
4. 三列 + 两个标记：阻塞、已取消。
5. 卡片只放用户关注的信息，卡片本来就不大。
6. 数据存宿主侧全局存储（跨项目），通过 `workspaceId` 弱关联对话目录。

## 3. 概念边界

DSH 里已有四个长得像「任务」的东西，必须划清，否则这个面板会变成第五套重复语义。

| 已有概念 | 与本插件的关系 |
|---|---|
| Goal（`ctx.goals`） | 会话内的单目标、自动续行。任务启动一个对话后，对话里要不要建 goal 是另一件事，本插件不代劳。 |
| Schedule（`ctx.schedule`） | 时间驱动。需要定时时，任务详情挂一个 schedule，任务只存弱引用 id，**不造第二套定时语义**。 |
| Team task（`ctx.agentTeams`） | agent 团队内部的协作任务，绑在 lead 会话日志上。不互通。 |
| `todo_write` | 会话内的待办清单，纯展示。不互通。 |

## 4. 数据模型

Storage domain：名称 `tasks`，version 1。

```ts
interface TaskRecord {
  id: TaskId                        // opaque，branded
  revision: number                  // CAS，防并发覆盖

  title: string                     // 索引用的短标题
  brief?: string                    // 任务描述：卡片显示前 2 行，启动时拼进首条消息

  stage: 'todo' | 'doing' | 'done'  // 看板列，手工
  blockedReason?: { code: string; message: string }  // 存在 = 阻塞
  cancelledAt?: string              // ISO 时间，存在 = 已取消

  parentId?: TaskId                 // 两层；只有根任务可被引用
  position: number

  workspaceId?: string              // 对话目录；空 = 未分组
  model?: { provider: string; model: string; reasoningEffort?: string }  // 偏好，启动面板预填
  agentPreset?: string

  activeSessionId?: string          // 最多一个
  previousSessionIds?: string[]     // 历史对话，仅存 id

  scheduleTaskIds?: string[]        // 弱引用
  createdAt: string
  updatedAt: string
}
```

要点：

- `stage` 与 `blockedReason` / `cancelledAt` **正交**。阻塞的卡留在原列加角标；取消的卡默认隐藏。这样不需要五列。
- `title` 与 `brief` 分开，但**不分裂语义**：标题是索引，`brief` 是描述兼执行说明——同一份文字，卡片显示摘要，启动时拼进首条消息。写一次，两处生效。
- `activeSessionId` 是唯一的活跃指针；换对话时旧 id 进 `previousSessionIds`。
- 引用一律**弱引用 + 存在性检查**，工作区或会话消失时降级显示，不抛错。

### 4.1 派生状态（不落库）

因为只有一个活跃对话，聚合逻辑就是「取它」，没有跨会话合并。

| 派生状态 | 判定 | 归类 | 视觉 |
|---|---|---|---|
| 待审批 | `pendingInput` 含 `approval` | **要你动** | 红点 + 进告警层 |
| 待回答 | `pendingInput` 含 `question` | **要你动** | 红点 + 进告警层 |
| 出错 | 最近 turn end reason = `error` | **要你动** | 橙点 + 进告警层 |
| 执行中 | `running` 且无 pending | 在跑 | 蓝点 |
| 空闲 | 有会话但没在跑 | 没事 | 灰点 |
| 未启动 | 无 `activeSessionId` | 没事 | 空心点 |

表内顺序即优先级阶梯（越前越优先）。

## 5. 界面规格

> 本节是给原型用的逐屏元素清单。所有文案以中文为准，实现时走 locale 字典。

### 5.1 入口

侧栏 panel list（`sidebar.panellist`）一个图标 + 文字「任务」。

### 5.2 看板主面板

```
┌──────────────────────────────────────────────────────────────┐
│ 任务                    [搜索] [筛选▾]        [新建任务]  [≡] │
├──────────────────────────────────────────────────────────────┤
│ ⚠ 2 件事在等你 · 接入支付、补测试                  [全部处理] │
├──────────────────────────────────────────────────────────────┤
│  待开始 3        │  进行中 2        │  已完成 7               │
│  ┌────────────┐  │  ┌────────────┐  │  ┌────────────┐        │
│  │            │  │  │            │  │  │            │        │
│  └────────────┘  │  └────────────┘  │  └────────────┘        │
│  ┌────────────┐  │  ┌────────────┐  │  ┌────────────┐        │
│  │            │  │  │            │  │  │            │        │
│  └────────────┘  │  └────────────┘  │  └────────────┘        │
│  [＋ 新建]       │                  │  [查看全部 7 条]       │
└──────────────────────────────────────────────────────────────┘
```

**顶栏**

| 元素 | 说明 |
|---|---|
| 标题「任务」 | 固定 |
| 搜索框 | 搜 `title` + `brief`，即时过滤 |
| 筛选器 ▾ | 工作区 / 模型 / 「显示已取消」；默认不显示已取消 |
| 「新建任务」 | 主按钮，见 5.8 |
| ≡ 菜单 | 多选模式的入口（可选：批量启动、批量取消） |

**告警条**

- 无「要你动」的任务时**整条不渲染**，不占垂直空间。
- 内容：`⚠ {n} 件事在等你 · {前两个任务名}{，等}`，右侧「全部处理」。
- 「全部处理」展开告警层列表，**不跳转**，不打断看板。

**列**

- 固定三列：待开始 / 进行中 / 已完成。列头显示计数，可点击折叠。
- 每列底部「＋ 新建」，在该列对应 stage 创建。
- 空列显示一行灰字引导（如「还没有进行中的任务」）。
- **已完成列默认只显示最近 10 条**，底部「查看全部 n 条」。避免看板被历史淹没。

**打开默认视图**：显示全部未取消任务，按 `position` 排序。

### 5.3 卡片

四行。信息重要性自上而下递减——标题最重，元信息最淡。

```
┌──────────────────────────────────┐
│▍接入支付                    ⚠    │  L1 标题
│ 把支付回调改成幂等，先补测试再动    │  L2 描述摘要（最多 2 行）
│ 老逻辑                           │
│ ● 待审批 · 修改 schema            │  L3 状态
│ acme-web · opus · 2/4            │  L4 元信息
└──────────────────────────────────┘
```

| 行 | 内容 | 规则 |
|---|---|---|
| **L1** | 标题 | 主文字色；单行省略；右侧角标位：阻塞（⚠）、已取消（划线灰字） |
| **L2** | `brief` 摘要 | 次要色；**最多 2 行**，超出省略；为空时整行不渲染（卡片自然变矮） |
| **L3** | 派生状态 | 见下表；带颜色，一行 |
| **L4** | `工作区名 · 模型短名 · 子任务进度` | 最淡（11px）；用 `·` 连接，**任一段没有就整段省略**；工作区为空显示「未分组」 |

L3 规则：

| 派生状态 | L3 文案 |
|---|---|
| 待审批 / 待回答 / 出错 | `● {状态} · {原因摘要}` —— 原因取审批或提问的标题，单行省略 |
| 执行中 / 空闲 | `● {状态} · {相对时间}`（如「5 分钟前」） |
| 未启动 | `● 未启动 · {创建相对时间}` —— 用创建时间暴露「放了很久没动」的事 |

**左侧 3px 色条**：红 = 要你动，蓝 = 执行中，灰 = 空闲，透明 = 未启动。

**明确不显示**（都进详情）：完整路径、优先级、标签、对话数量、token 用量、模型全名、更新时间戳。

**hover 有两件事，必须分开处理**：

1. **操作按钮**：右上角**立即**浮出「开始」（▶）和「更多」（⋯），不占常驻空间。
2. **悬浮信息卡**：延迟 **500ms** 后出现，补全卡片上被截断的内容，见 5.9。

**窄卡截断顺序**：描述 → 元信息右段（先丢子任务进度、再丢模型），**工作区名和状态永不截断**——它们是判断「这张卡在哪、要不要管」的底线。

**高度不强制等高**：描述为空或很短时卡片自然变矮，看板列内顶部对齐。

### 5.4 详情

形态：右栏 tab（`sidebar.right.pane.tab`），**不打断看板**。

分区顺序：

1. **标题** —— 原地编辑
2. **状态行** —— stage 切换 + 「标记阻塞」/「取消任务」
3. **活跃对话**
   - 有：状态点 + 状态文字 +「打开对话」+「换一个对话」
   - 执行中时「换一个对话」禁用，提示「对话执行中」
   - 无：「还没有对话」+「开始」主按钮
4. **执行说明**（brief）—— 多行文本，此处才说明「这段会作为首条消息发给 agent」
5. **工作区** —— 目录名 + 完整 path（**这里**才显示 path）+ 选择器
6. **模型 / 预设** —— 显示当前偏好；未设置显示「跟随默认」
7. **子任务**（仅根任务）—— 列表 + 勾选 +「添加子任务」+ 进度 `2/4`
8. **历史对话**（折叠，仅数量 > 0 时出现）—— 时间 + 打开
9. **定时**（M7）—— 关联的 schedule 列表 +「添加定时」
10. **危险区** ——「取消任务」

### 5.5 启动面板

模态小面板，不是整页，不遮挡看板上下文。

```
┌────────────────────────────────────┐
│ 启动任务：接入支付                  │
├────────────────────────────────────┤
│ 工作区   [acme-web            ▾]   │
│ 模型     [opus-4              ▾]   │
│ 预设     [默认                ▾]   │
│                                    │
│ 首条消息                           │
│ ┌────────────────────────────────┐ │
│ │ 接入支付                        │ │
│ │                                 │ │
│ │ （brief 内容）                  │ │
│ └────────────────────────────────┘ │
├────────────────────────────────────┤
│                      [取消] [开始] │
└────────────────────────────────────┘
```

规则：

- 四个字段**全部预填**：工作区 = 任务的；模型 = 任务偏好，无则全局默认；预设 = 任务的，无则「默认」；首条消息 = `title` + 空行 + `brief`。
- 首条消息可编辑，**编辑不回写任务**（一次性）。想长期改就改 brief。
- `brief` 为空时，首条消息框**自动聚焦**并显示占位提示「补充这次要它做什么」。
- 缺工作区：该字段高亮提示，但仍允许启动（落在未分组）。
- 已有活跃对话且**空闲**：面板顶部多一行二选一——「接着用现有对话」/「新开一个对话」，默认「接着用」；选「接着用」时隐藏其余字段，直接打开对话。
- 已有活跃对话且**执行中**：不打开面板，直接提示「已有对话在执行」。

### 5.6 批量启动

- 多选模式：从 ≡ 菜单进入，卡片左上角出现复选框。
- 选中后顶栏替换为：`已选 3 项  [开始所选] [取消]`。
- 「开始所选」**不弹面板**，按每个任务自己的偏好直接启动。
- 缺工作区或未配模型的任务照常启动（用默认），不阻塞。
- 已完成、已取消、已有执行中对话的任务**被排除**，结果里说明排除了几个及原因。

### 5.7 会话行徽标（M7）

侧栏会话行前（`sidebar.session.row.leading`）加一个小色点，颜色同所属任务卡的派生状态；hover（`sidebar.session.row.hover`）显示任务名。点击跳看板并定位该卡。

### 5.8 新建任务

**新建弹框**：顶栏或列底「＋ 新建」打开居中弹框，背景看板不改变布局：

```
┌──────────────────────────────────────────┐
│ 新建任务                            [×]  │
│ 标题        [这次要做什么？             ] │
│ 描述（可选）[目标、背景或验收标准…      ] │
│ 工作区（可选）       模型偏好（可选）     │
│ [未分组          ▾]  [使用默认模型    ▾] │
│ 任务分类    [待开始                   ▾] │
│ 保留当前标签页草稿          [关闭] [创建] │
└──────────────────────────────────────────┘
```

- 标题必填；描述可选，但**它是卡片摘要和首条消息的共同来源**，空着卡片就会空一半
- 标题和描述在上方；工作区与模型各占半行，窄屏改为单列。只有标题必填，工作区默认未分组，模型默认不保存显式偏好。
- 打开时焦点进入标题，Tab 留在弹框内；Esc、关闭按钮或背景点击收起，焦点返回入口。描述允许回车换行。
- 建好后落在当前列的 stage
- 工作区从 Host 注册目录中选择；模型从配置的提供方分组目录中选择。服务不可用时可重试或不绑定，创建仍可进行。
- 输入、分类和偏好保存在当前标签页草稿中；结果未知时锁定原参数并重试同一请求。成功后清除草稿。

看板卡片保持原型的四层信息布局，分类操作收进悬浮菜单。当前实现只展示实际保存的元信息和未启动状态，会话派生状态、启动与审批操作按后续里程碑接入。

新建和改列已通过共享 SSE 自动同步到其他页面；底部显示连接状态，断线自动获取完整快照恢复，草稿和筛选保留。会话状态在任务与会话关联完成后复用该通道，验收见 [实时同步验证](step-4-verification.md)。

### 5.9 悬浮信息卡

用途：**补全卡片上被截断的内容**，不承载操作。

```
┌────────────────────────────────────────┐
│ 接入支付                                │
│ 把支付回调改成幂等，先补测试再动老逻辑。 │
│ 现有实现见 src/pay/callback.ts，注意    │
│ 重试窗口要跟网关配置对齐。               │
│ ─────────────────────────────────────  │
│ 工作区   acme-web                      │
│          F:\work\acme\web              │
│ 模型     claude-opus-4 · anthropic      │
│ 预设     默认                            │
│ 状态     待审批 · 修改 schema · 5 分钟前 │
│ 子任务   2/4                            │
└────────────────────────────────────────┘
```

内容只放**卡片上被截掉或放不下的**，顺序固定：

| 段 | 内容 | 说明 |
|---|---|---|
| 1 | 标题 | 完整，不省略 |
| 2 | 完整 `brief` | 最多 8 行，超出可滚动 |
| 3 | 工作区 | 目录名 + **完整 path** |
| 4 | 模型 / 预设 | 全名 + provider；未设置显示「跟随默认」 |
| 5 | 状态 | **完整**原因，不省略 |
| 6 | 阻塞原因 | 仅阻塞时出现，全文 |
| 7 | 子任务进度 | 仅有子任务时出现 |

规则：

- 延迟 **500ms** 出现，鼠标离开立即消失。扫过卡片不该弹。
- 锚定卡片定位（不跟随鼠标），默认在卡片右侧；右侧空间不足翻到左侧。
- **`pointer-events: none`**——纯展示，鼠标穿透。这样右上角的操作按钮始终可点，不会出现「想点开始却弹出了信息卡」。
- 段落 3 之后用次要色，弱化，避免信息卡比卡片本身还抢眼。
- 触屏不触发（没有 hover 概念）；移动端靠点开详情。
- 键盘 Tab 聚焦卡片时同样显示，无障碍对等。

## 6. 交互规则

### 6.1 启动流程

```
点「开始」
 ├ 有活跃对话 且 执行中        → 提示「已有对话在执行」，终止
 ├ 有活跃对话 且 空闲          → 询问「接着用 / 新开一个」
 │    ├ 接着用   → 直接打开该对话，不建新会话
 │    └ 新开一个 → 走下面新建流程，旧 id 移入 previousSessionIds
 └ 无活跃对话                  → 开启动面板 → 确认后：
       1. 持久化 launch 请求、预分配 sessionId，phase = prepared
       2. create({ sessionId, workspaceId, agentPreset })；持久化 phase = created
       3. 若 model → selectModel({ sessionId, ... })；持久化 phase = sending
       4. prompt({ requestId, sessionId, mode: 'queue', content })
       5. 写回 activeSessionId、phase = complete；stage: todo → doing
       6. 打开该对话
```

失败处理：

- 任一步失败保留最新已落盘进度；完成绑定前不修改 `activeSessionId`，候选会话 ID 保存在 `launch` 中，可打开查看或恢复。`prepared / created` 可显式结束启动，并把候选会话引用加入历史。
- 投递已开始而结果未知，或投递成功后绑定落盘失败：恢复时复用 DSH 的消息请求 ID，不重建会话。`sending` 不开放结束操作；只有确认投递接收后才绑定任务。Host 重启不自动重发。
- DSH 的具名 `create` 在指定会话已非空时可能新建其他 ID，因此恢复先被动检查已保存的会话；存在时复用，不再次调用 `create`。

### 6.2 状态与拖拽

| 动作 | 结果 |
|---|---|
| 拖到任意列 | 只改 `stage`，**不启动任何东西** |
| 拖到「已完成」 | `stage = done`；若活跃对话仍在跑，提示「对话仍在执行，是否停止」 |
| 标记阻塞 | 写 `blockedReason`；卡片留原列 + 角标 + 进告警层 |
| 取消任务 | 写 `cancelledAt`；默认从看板隐藏；若活跃对话在跑，询问是否停止 |
| 恢复取消 | 清 `cancelledAt`，卡片回原列 |

**仅做取消，不做删除。** 取消能满足「我不想做了」，删除涉及对话关联清理，风险大，留到以后。

### 6.3 告警层

收集条件：`stage !== 'done'` 且未取消 且 派生状态 ∈ {待审批, 待回答, 出错}。

- 点击「全部处理」展开列表，每条：任务名 + 原因摘要 +「打开对话」（直接切到该对话处理）。
- 全部处理完 → 告警条自动消失。

### 7.3 关键架构选择：聚合状态流

看板要实时，DSH 0.2.2-rc.1 的 `observeState` 每会话一条流，且独立的 pending-input 变化不会触发该流。Host 持有一组全局会话事件监听，并按可配置周期（默认 2 秒）被动读取活跃会话状态；相同会话 ID 去重，浏览器数量不增加 Host 的状态观察器。

做法：插件 Host 侧通过 `ctx.connection.fetch.register()` 提供一条 SSE 聚合流，推送「所有属于任务的活跃会话」的状态快照 + 增量。客户端只订一条。任务读写由同一服务注册的 `/api/dsh-plugin-tasks/rpc` 承接，Client 使用 `connection.rpc.call()`；具体步骤与 DSH 0.2.2-rc.1 的兼容处理见 [通信与持久化实施计划](implementation-plan.md)。

- Host 侧本来就持有 `taskId → activeSessionId` 映射
- 监听会话事件和 Agent 状态变化，合并进行中的刷新；周期采样补足待审批、待回答和归档变化
- 空闲且游标改变时读取会话最近 turn 结果，识别错误；丢失、归档和读取失败显式降级
- 客户端一条流喂全部卡片

这是 P0 的一部分，不是后置优化。

## 9. 待定项与风险

1. **`selectModel` 会改全局默认模型。** 已确认这是 DSH 的刻意行为（选模型 = 改默认）。启动面板里显式选择即视为用户同意。但**批量启动**用任务偏好时会静默改默认，需要一个配置项：任务偏好是否同时设为默认。默认关。
2. **引用会消失。** 工作区被删、会话被归档。全部弱引用 + 存在性检查，降级为「未分组」「对话已归档」，绝不抛错。
3. **取消的卡去哪。** 默认隐藏，靠筛选器「显示已取消」找回。若用户找不到会困惑，筛选器需要显式入口，不能只藏在菜单里。
4. **详情右栏必须是浮层，不能挤压看板。**（已用实测数据定案，见下）
   - 原型实测（1264×1004 视口）：侧栏 240 + 主区 1024，详情抽屉占 410 后看板只剩 614px；而三列最小值合计需要 904px → **横向溢出，第三列被推出可视区**。
   - 三列单独显示时：1024 可用 → 每列约 309px，正好落在 280–380 区间，没有问题。
   - 真实 DSH 的右栏本身就是浮层：`AppFrame.module.css` 注释写明「With no track the panel hangs over the centre from a zero-width column」，`layout.openRightbar(track, fullscreen)` 的 `track` 参数就是控制中间列是否让位。
   - **结论**：详情用 `openRightbar(track = false)`，看板保持全宽（1264 − 288 侧栏 ≈ 976px → 每列约 304px）。原型视觉几乎不用改，但绝不能做成挤压式。
   - 列宽下限 **280px**：实测 258px 卡片宽度下，2 行描述刚好放满且不溢出，再窄就会明显截断。
5. **brief 为空时首条消息信息量不足。** 靠启动面板的聚焦提示兜底；若实际使用中仍普遍为空，再考虑首条消息里强制补一句执行框架。
6. **是否给 agent `task_run` 工具。** 启动对话是重操作，可能需要「当前回合有直接用户来源」的授权约束（对齐 Goals 的规则）。M6 只先做读写，`task_run` 单独评估。
