# 步骤 3 验证记录

2026-11-16，DSH 0.2.2-rc.1，现有 `web` profile 的本地 link 安装。看板操作闭环已完成；聚合实时同步属于步骤 4。

## 实现

`client.js` 保持手写 ModuleLoader factory，只从 factory 的 `require('react')` 取得 React。一个在 `apply` 中创建的数据来源提供 `getSnapshot / subscribe`、RPC 动作、草稿及 pending 状态；slot 通过 `hooks: { tasks }` 绑定 `useTasks(selector)`。组件只接收注入的状态和回调。

看板提供标题/可选描述表单、三列真实卡片、即时搜索和分类下拉框。创建默认进入 `todo`，改列只调用 `set-stage` 保存分类。只有收到有效的持久化成功记录才更新卡片；刷新与写操作不重叠，不同写响应按 revision 合并。

重复创建和同一任务的重复改列在 pending 期间被禁止。创建结果未知时保留标识和原始参数，锁定表单并重试同一请求。当前标签页的 `sessionStorage` 保存草稿和待确认请求，页面刷新后可继续；成功后清除。存储不可用时仅在内存保留，关闭标签页或清除浏览器存储不保证草稿恢复。

改列冲突或结果未知时显示目标分类，暂停该卡片的修改，要求刷新后重新选择。列表失败保留已加载卡片并暂停写入，重试后恢复；持久化状态不确定时隐藏旧数据，提示重新启用插件或重启 DSH。Client 每次 RPC 等待上限为 30 秒；取消或超时不意味着撤销已提交写入。

## 自动测试

`npm test`：34 项全部通过。保留前两步的真实 HTTP、鉴权、持久化、并发和卸载测试，并新增 9 项 Client 测试：

- 实际组件事件回调完成创建、标题/描述搜索、列计数、改列和刷新。
- pending 创建抑制重复提交与刷新，业务失败保留可编辑输入，不生成假卡片。
- Host 已提交但创建响应丢失；卸载/重新加载 Client 后重试相同请求，只产生一条记录。
- 真实旧 revision 冲突保留目标分类和新建草稿，刷新后使用新 revision 操作。
- 已提交改列但响应丢失时，禁止盲目重试，刷新恢复实际分类。
- 卸载取消 pending 写请求并抑制迟到发布，保留待确认的创建标识。
- 畸形 TaskRecord、重复 id 列表及畸形创建结果不能成为正常卡片。
- 写入状态不确定时隐藏旧记录并保留创建标识。
- 较晚到达的创建重放响应不会覆盖已收到的更高 revision。

测试执行发布的浏览器 factory 和真实 Cordis 注入。组件保持纯函数，测试展开实际 React 元素并调用其事件回调；renderer 的 hook 绑定和浏览器交互另用真实 Web profile 验证。

## 真实 Web 页面

通过支持的 CLI 启动：

```text
dsh --profile web --patch <临时 storage.overlay.yml> --no-open --port 0
```

仅将 `storage-json.config.root` 指向独立临时目录，没有写入实际 DSH home 的任务文件。浏览器连接工具中断后，使用临时目录安装的 Playwright 和独立无窗口 Edge 完成页面验收；浏览器测试依赖不进入插件的依赖或发布包。

实际页面验证：

1. 打开侧栏任务，空列表显示三列零计数。
2. 用表单创建带中文标题和多行描述的任务，卡片只在成功后出现。
3. 下拉框改为 `doing`，卡片移动且计数更新。搜索 `CALLBACK` 匹配描述，搜索不存在内容显示零匹配。
4. 看板刷新和浏览器页面刷新后恢复相同卡片与分类。
5. 拦截一个创建请求，在真实 Host 提交后替换响应为 503；页面保留输入并显示创建结果未知。页面刷新后点击重试，两次创建的输入完全一致，只保留一个对应任务。
6. 第二个已鉴权浏览器页面修改首个任务；第一个页面的旧版本修改显示冲突。点击卡片刷新恢复最新分类，另一份未提交草稿保持原样。
7. 模拟列表 503，保留两张已有卡片且两个分类下拉框均禁用；点击重试后恢复。
8. 停止属于本次验证的 Host 及子进程，再用相同存储覆盖配置启动新 Host。两条完整存储记录（包括 id、revision、stage、时间戳和创建元数据）与重启前完全一致；看板恢复两张卡片，计数为 `1 / 0 / 1`。

整个页面验证没有出现 `pageerror`。已查看空看板、搜索、表单冲突和重启后的截图。不同页面目前通过手动刷新同步；SSE、会话派生状态和拖拽仍按后续步骤实施。
